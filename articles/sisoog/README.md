<h1 dir="rtl" align="right">از دستگاه بسته تا فریمور قابل نگهداری؛ OpenWrt برای ZLT X28 و X28 PRO</h1>

**مجموعه آموزشی سیسوگ — علی نادری پاریزی — بازبینی: ۲۰۲۶-۱۱-۱۰**

> **بازطراحی آموزشی در حال بازبینی:** [طرح جریان دوازده‌قسمتی](revision-plan.md) و [دفتر issueها و شواهد](revision-evidence.md) آماده‌ان. پیشنهاد جدید با یه دستگاه بسته شروع می‌شه و هر قسمت یه پیشرفت قابل مشاهده داره؛ معرفی Preloader، LK، Device Tree، امضا و ABI پیش از استفاده گنجانده می‌شه. v0.78 طبق تأیید نویسنده در CI در حال ساخته‌شدنه. فهرست زیر هنوز ده متن موجوده؛ شماره‌ها و متن مقاله‌ها در این مرحله جابه‌جا نشده‌اند.


این پروژه با دسترسی‌گرفتن به یه مودم 5G شروع شد، اما هدفش همون‌جا متوقف نشد. بعد از شناخت سخت‌افزار و firmware اصلی، مسیر به ساخت RootFS، راه‌اندازی 5G در OpenWrt، ساخت module، feed اختصاصی امضاشده، پشتیبانی از مدل معمولی و PRO و ارتقای A/B رسید. این مجموعه هم روایت همین مسیر مهندسیه، هم راهی برای یادگرفتن مفاهیمی که توی یه پورت واقعی کنار هم قرار می‌گیرن.

منظور از دستگاه «بسته» در این روایت، محدودیت دسترسی و نگهداری firmware هست؛ دسترسی root، برداشتن قفل SIM و جایگزین‌کردن سیستم‌عامل سه کار جدا هستن. روش انجام یکی رو نباید خودکار روش انجام بقیه معرفی کنیم. هدف فعلی، یه CPE سلولی با مدیریت استاندارد OpenWrt هست؛ هنوز به معنی پشتیبانی رسمی upstream یا جایگزینی همه driverهای vendor نیست.

**از Tozed بابت در اختیار گذاشتن SDK ممنونم.** این دسترسی در شناخت پلتفرم و توسعه اجزای سازگار ارزشمند بود. تشکر از سازنده به معنی تأیید رسمی فریمور مستقل پروژه یا اجازه انتشار تمام فایل‌های SDK نیست.

چهار قسمت اول روایت snapshot اولیه پروژه‌ان؛ مبنای اون‌ها در خود متن مشخص شده. شش قسمت بعدی، مسیر توسعه بعدی رو تا بازبینی ۱۰ نوامبر ۲۰۲۶ دنبال می‌کنن. اگه فقط دنبال امضا و ارتقا هستید، از قسمت هشتم شروع کنید، ولی برای تصمیم مربوط به NAND و slotها اول قسمت دوم رو بخونید. برای مشارکت در توسعه، قسمت‌های پنجم تا هفتم پایه مناسب‌تری دارن.

<h2 dir="rtl" align="right">چه چیزی انجام شده و چه چیزی هنوز هدفه؟</h2>

وجود یه گزینه توی رابط یا یه script توی مخزن، نتیجه آزمون نیست. برای همین، این مجموعه وضعیت‌ها رو از هم جدا می‌کنه:

<div dir="rtl" align="center">

| موضوع | شاهد فعلی در این بازبینی | چیزی که هنوز نباید ادعا کنیم |
| ---: | ---: | ---: |
| تصویر native | userspace نسخه 23.05.5 روی Kernel vendor 4.19.205؛ بوت روی X28 و PRO ثبت شده | target رسمی OpenWrt یا Linux mainline |
| feed اختصاصی | index امضاشده، packageهای برد و moduleهای هماهنگ؛ نصب و reboot ثبت شده | بازکامپایل تمام بسته‌های رسمی یا پشتیبانی همه kmodها |
| ساخت driver و module | WireGuard، TPROXY و مجموعه moduleهای feed؛ هرکدوم با دامنه آزمون خودش | جایگزینی کامل درایور مودم، Wi-Fi و BSP |
| امضای image | رد unsigned و tampered و پذیرش signed در آزمون ۵۳d | تکمیل همه آزمون‌های انقضا، revocation و CI |
| ارتقای A/B | چرخه واقعی A → B → A در ۵۳d؛ کد جدید target غیرجاری رو انتخاب می‌کنه | تحمل قطع برق و fallback جامع آزموده‌شده در همه نسخه‌ها |
| خودکارسازی | workflow ساخت و انتشار، بررسی نسخه و upgrade با تأیید کاربر در source موجوده | OTA خودکار و بدون حضور کاربر روی همه دستگاه‌ها |
| پشتیبانی چندمدلی | دو نمونه X28 و PRO و رفع تفاوت‌های مشخص | سازگاری تمام مدل‌های اپراتوری، V-Pro یا هر revision |

</div>

در آغاز این بازبینی، بعضی overviewها هنوز sysupgrade رو آینده می‌دونستن؛ نسخه محلی STATUS در ۱۰ نوامبر این وضعیت رو تصحیح کرده. برای قسمت‌های تازه، source فعلی، همین وضعیت به‌روز و ثبت آزمون‌های تاریخ‌دار ۵۲ و ۵۳ مبنا قرار گرفتن. آزمون درجا روی A، آزمایش انتقال به B و سیاست فعلی «همیشه slot غیرجاری» هم مراحل مختلف توسعه‌ان؛ اون‌ها رو یه رفتار ثابت در تمام releaseها معرفی نکردیم.

<h2 dir="rtl" align="right">قرارداد این مقاله‌ها با خواننده</h2>

- متن برای آموزش و بازبینی مهندسیه؛ دستور عمومی فلش هر دستگاه هم‌نام نیست. عملیات مخرب باید از مسیر بررسی‌شده فلشر و با backup همون واحد انجام بشه.
- commandهای تاریخی، نمونه interface و commandهای بررسی از هم مشخص شدن. لاگ ترمینال، benchmark یا نتیجه سخت‌افزاری ساخته نشده.
- امضای package، امضای تصویر sysupgrade و احراز firmware در bootloader سه لایه متفاوتن.
- OTA، تعویض خودکار slot، حفظ config و برگشت از خرابی باید هرکدوم با شاهد خودشون معرفی بشن؛ موفقیت یکی اثبات بقیه نیست.
- عدد packageها و moduleها به snapshot منبع وابسته‌ست. تعداد پارتیشن، تعداد module loadشده و تعداد package یه چیز نیستن.
- کلید خصوصی، credential، اطلاعات SIM، شناسه دستگاه، dump calibration و firmware اختصاصی همراه مقاله منتشر نمی‌شن.

<h2 dir="rtl" align="right">موضوع‌های مناسب برای ادامه، وقتی شاهدش آماده شد</h2>

این‌ها عنوان پیشنهادی فصل‌های بعدی‌ان، نه قابلیت تمام‌شده پروژه:

- «USB-C فقط Recovery نیست؛ ساخت شبکه NCM برای اتصال مستقیم به کامپیوتر»؛ بعد از تکمیل بسته و آزمون پایدار روی مدل‌ها.
- «وقتی برق وسط upgrade قطع می‌شه»؛ آزمایش کنترل‌شده write، misc و fallback روی واحد آزمایشی.
- «حفظ تنظیمات میان دو تصویر؛ migration و overlay در OpenWrt»؛ بعد از آزمون واقعی -k و اختلاف UUID.
- «از Kernel اختصاصی به پورت قابل نگهداری»؛ مسیر عملی BSP، modem و Wi-Fi تا Kernel جدید.
- «OTA قابل اعتماد برای یه CPE سلولی»؛ انتخاب نسخه، امضا، زمان‌بندی و گزارش شکست، بعد از آزمون end-to-end.
- «اندازه‌گیری Wi-Fi و 5G بدون مقایسه گمراه‌کننده»؛ آزمایش با SIM، محل، client و شرایط حرارتی کنترل‌شده.
